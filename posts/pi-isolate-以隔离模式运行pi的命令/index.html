pi-isolate — 以隔离模式运行 Pi 的命令

发表于 2026-07-29 分类于 项目介绍
在任意目录以项目级隔离配置运行 Pi Coding Agent 的全局命令。symlink 凭证、生成过滤后的 settings.json、按需拣选全局资源，避免多项目间配置污染和凭证泄露。

项目简介

pi-isolate 是一个全局命令，让你在任意目录以 项目级隔离配置 运行 Pi Coding Agent。

  • 仓库地址：https://github.com/guyu-guyu/pi-isolate
  • 主要语言：JavaScript (Node.js ≥ 18)
  • 安装：npm install -g github:guyu-guyu/pi-isolate

解决什么问题

默认情况下 Pi 读取全局配置 ~/.pi/agent/（包含所有包、扩展、技能、凭证等）。在多个项目间切换时会有几个头疼的问题：

  • 全局 packages 字段会把所有装过的包都加载进来，无法按项目隔离
  • auth.json 含 API key，直接复制到项目目录有泄露风险（误 git add 就完了）
  • 手写隔离脚本每个项目都要拷一份，更新成本高

pi-isolate 把隔离启动做成一个全局命令：任意目录跑 pi-isolate 就能以隔离模式启动 Pi。

使用

参数分类：pi-isolate 识别自己的 flag（见下表），其余参数原样透传给 pi --approve。要强制透传（比如把 --help 传给 pi），用 -- 分隔：pi-isolate -- --help。

Flag 行为
-h / --help 显示 pi-isolate 帮助并退出
-V / --version 显示版本并退出
--list 列出全局已装的 packages / extensions / skills，标记已被拣选的
--pick 进入简易 TUI：↑↓/jk 移动、Space 勾选/取消、Enter 应用、q/Esc 取消
--add-package <spec> 从全局拣选一个 package 到隔离目录
--remove-package <spec> 移除已拣选的 package
--add-extension <name> 从全局拣选一个 extension
--remove-extension <name> 移除已拣选的 extension
--add-skill <name> 从全局拣选一个 skill
--remove-skill <name> 移除已拣选的 skill

资源拣选

默认生成的 settings.json 不带 packages / extensions / skills，避免全局资源泄入隔离环境。需要某个资源时，用 --add-* 把它从全局"拣选"到 .pi-isolated/：

机制：

  • packages：当 settings.json 的 packages 非空时，把全局的 npm/ 和 git/ 目录 整体 symlink 到 .pi-isolated/。这样 Pi 启动时能在磁盘上找到所有引用的包及其传递依赖，不会触发重装。最后一个包被移除后 symlink 自动删除。
  • extensions / skills：以单个 symlink 方式链入 .pi-isolated/（避免整目录 symlink 触发 Pi 的扩展自动发现）。

所有资源在 settings.json 对应字段登记，与全局保持同步（全局更新即生效）。

为何 packages 整目录、extensions 逐个：Pi 只加载 settings.json packages 列出的包（不扫描目录），所以整目录 symlink 不会让多余包加载。但 extensions 会从 extensions/ 目录 自动发现，整目录 symlink 会把全局所有扩展都带进来——所以 extensions 必须逐个 symlink。skills 同理。

它做了什么

在当前目录创建 .pi-isolated/，内含：

文件 类型 说明
.gitignore 真实文件 * + !.gitignore，防止目录内任何东西被提交
auth.json symlink 指向 ~/.pi/agent/auth.json，不含数据，误提交也不泄露
models.json symlink 指向 ~/.pi/agent/models.json
settings.json 真实文件 仅首次生成，从全局过滤出基础字段；不带 packages/extensions；skills 固定写入 ["!**/.agents/skills/**"] 屏蔽固定路径

然后设置 PI_CODING_AGENT_DIR=.pi-isolated 并 exec pi --approve "$@"。

启动检查

以 launch 模式启动 Pi 前会做两项检查：

检查 1：npm/ 和 git/ 目录 symlink 一致性 —— 若 packages 非空但对应目录缺失或不再是 symlink，会自动重建；若变成了真实目录（可能是绕过 pi-isolate 跑 pi install 留下的），会提示是否删除改为 symlink。

检查 2：redirected 与全局的 packages 差异 —— 对比两边 packages 字段，对每个在隔离配置中存在、但在全局中不存在的包，提示三选一：

设计要点

  • symlink 而非复制 —— auth.json / models.json 是指针，不含真实数据，即使 .pi-isolated/ 被误提交也不会泄露凭证。全局改了即生效。
  • settings.json 只生成一次 —— 首次从全局过滤复制，之后不再覆盖。用户在隔离模式下的 pi config 修改、手动编辑都会保留。要重置直接删 settings.json 再跑一次 pi-isolate。
  • 不带 packages —— 首次生成的 settings.json 不含 packages / extensions 字段，需要什么资源用 --add-* 从全局拣选。
  • 幂等 —— 重复运行安全。symlink 每次重建，settings.json 跳过，.gitignore 缺失才补。

安全

  • .pi-isolated/.gitignore 会忽略目录内一切（除了自身）
  • auth.json / models.json 是 symlink，不含数据
  • settings.json 是过滤后的真实文件，无密钥

双保险：即便项目根 .gitignore 没加 .pi-isolated/，目录内的 .gitignore 也会拦住 git add。
